# eum-camp 온보딩·설정마법사 명료성 재검토

- 검토일: 2026-09-02
- 범위: `src/auth/LoginScreen.tsx`, `src/auth/SetupScreen.tsx`, `src/auth/EventSetupWizard.tsx`, `src/App.tsx`, `src/auth/types.ts`, `docs/AI_SETUP_GUIDE.md`
- 산출: 설계·문구·흐름 검토만. 코드 수정 없음.
- 브라우저: 이 좌석에는 `mcp__playwright__*`가 노출되지 않아 eum-camp 시각 캡처는 하지 않았다. 현재 상태는 소스 직접 판독이며, 참고 사이트는 HTML과 연결 JS 번들을 직접 HTTP GET해 문자열을 확인했다. 시각 레이아웃 평가는 보류한다.

## 결론

eum-camp의 인증·행사 설정 흐름은 기능적으로 구성되어 있으나, 사용자가 “내 역할”, “왜 입력하는지”, “다음 행동”을 한눈에 파악하는 명료성은 bible-school-os 참고 패턴보다 약하다. 기능 추가나 역할 확장이 아니라 역할·목적·단계·CTA 문구를 보강하는 것이 우선이다.

## 참고점 — bible-school-os 직접 수집

`GET https://bible-school-os-miracle.web.app/` 결과는 HTTP 200, HTML 515바이트이며 title은 `성경학교 OS - 시즌 사역 기획 & 신청 통합 플랫폼`이었다. HTML이 지정한 `/assets/index-BbyitPQI.js`도 직접 GET해 703,605바이트를 확인했다. 번들에서 다음 패턴을 문자 단위로 확인했다.

| 참고 패턴 | 직접 확인한 표현·행동 | eum-camp 적용 원칙 |
|---|---|---|
| 역할 라벨 | `👑 총괄 관리자 (기획/예산/설정)`, `👥 부서 교사 (승인/특이사항 메모)`, `🍏 지원 스태프 (읽기 전용/식사/의료)` | 실제 eum-camp 역할 2개를 유지하면서 역할명+권한 요약만 차용 |
| 조건부 입력 목적 | 관리자 선택 시에만 `🔑 관리자 가입 인증코드`를 표시하고, 오류 문구에서 총괄 관리자 가입 목적을 설명 | 관리자 비밀번호와 운영위원 PIN의 사용자·용도를 입력 전 설명 |
| 다음 행동 CTA | `회원가입 완료 및 시작`, `관리자 콘솔 접속`, `처음이신가요? 계정 새로 가입하기`, `이미 계정이 있으신가요? 로그인하기` | “설정 완료”보다 저장 후 이동 결과를 말하는 CTA 사용 |
| 데모 진입 | `📢 개발 및 테스트용 데모 계정`과 데모 계정 정보, `데모 어드민` 표시 | 기존 eum-camp 데모 정책은 바꾸지 않고 체험/설치 안내만 분리·명료화 |

참고 사이트의 텍스트 존재는 **High**(직접 HTTP 200 및 번들 실측), 실제 시각 배치는 **미검증**(Playwright 도구 부재), eum-camp에 그대로 맞는다는 주장은 **Low/추정**(역할·보안 모델이 다름)으로 분류한다.

## 최종 문구 초안

### LoginScreen — 첫 진입/재접속

- 단계 라벨: `이음 캠프 · 1단계 / 운영 화면 접속`
- 첫 진입 제목: `우리 교회 운영자를 먼저 설정해 주세요`
- 설명: `이 화면은 수련회 운영 데이터를 관리할 사람을 위한 접속 설정입니다. 관리자 비밀번호를 만들면 다음 단계에서 행사 정보를 입력할 수 있습니다.`
- 이름 라벨: `관리자 표시 이름`
- 이름 도움말: `운영 화면과 변경 기록에 표시될 이름입니다. 예: 김○○ 목사, 수련회 운영팀`
- 비밀번호 라벨: `관리자 비밀번호 · 8자 이상`
- 비밀번호 도움말: `참가자 명단과 행사 설정을 관리할 때 사용합니다. 운영위원에게는 이 비밀번호를 공유하지 말고, 별도 조회용 PIN을 사용하세요.`
- CTA: `관리자 설정 저장하고 다음 단계로`
- 재접속 제목: `이음 캠프 운영 화면에 접속`
- 역할 안내: `관리자: 행사·참가자·운영 설정을 관리합니다. 운영위원: 안내받은 PIN으로 필요한 운영 정보를 확인합니다.`

### SetupScreen — 관리자 보안 설정

- 단계 라벨: `1단계 / 관리자 접속 설정`
- 제목: `관리자 접속 정보를 만들어 주세요`
- 설명: `이 정보는 이 브라우저에 저장되며, 참가자 명단과 행사 설정을 관리할 때 사용합니다. 설정을 마치면 행사 기본 정보를 입력합니다.`
- 보안 안내: `관리자 비밀번호는 관리자만 사용합니다. 운영위원에게 공유할 조회용 PIN은 행사 화면에 들어간 뒤 별도로 만들 수 있습니다.`
- CTA: `저장하고 행사 정보 입력하기`
- 완료 메시지: `관리자 설정이 저장되었습니다. 이제 행사명과 일정을 입력해 주세요.`

### EventSetupWizard — 행사 기본 정보

- 단계 라벨: `2단계 / 행사 기본 정보`
- 제목: `우리 교회 행사를 등록해 주세요`
- 설명: `행사명과 일정만 먼저 입력해도 시작할 수 있습니다. 입력한 내용은 로그인 화면과 운영 대시보드에 표시되며, 나머지 정보는 나중에 설정에서 채울 수 있습니다.`
- 필수 안내: `먼저 행사명과 시작일·종료일을 입력하세요.`
- 선택 안내: `주제, 장소, 주관 단체, 문의 담당자는 참가자 안내에 필요할 때 추가하세요.`
- CTA: `행사 정보 저장하고 운영 화면 열기`
- 검증 실패: `행사명과 시작일·종료일을 입력하면 운영 화면을 열 수 있습니다.`

### PendingSetupScreen — 운영위원 대기

- 제목: `관리자 설정을 기다리고 있습니다`
- 상태 라벨: `현재 상태 · 행사 정보 미등록`
- 설명: `현재 계정은 운영위원 권한입니다. 관리자가 행사명과 일정을 먼저 저장하면 참가자·운영 정보를 확인할 수 있습니다.`
- 다음 행동: `관리자에게 행사 기본 정보 저장을 요청한 뒤, 완료 안내를 받으면 이 페이지를 새로고침해 주세요.`

## 제안 흐름

```text
첫 방문
  → [1단계] 관리자 접속 설정
      역할·권한 요약 + 비밀번호 목적 설명
      → 저장하고 행사 정보 입력하기
  → [2단계] 행사 기본 정보
      필수 3개(행사명·시작일·종료일) 우선 + 선택 정보는 나중에 가능
      → 행사 정보 저장하고 운영 화면 열기
  → 운영 대시보드
      → 관리자: 진행위원 인증 설정에서 조회용 PIN 추가
      → 운영위원: 안내받은 PIN으로 접속, 행사 정보 등록 전에는 대기
```

이 흐름은 실제 라우팅(`App.tsx:441-449`)과 권한 정의(`types.ts:3-7`)에 맞췄다. 참고 사이트처럼 역할을 3개로 늘리거나 별도 회원가입 계정을 도입하는 내용은 채택하지 않는다.

## 검토 한계 및 구현 전 메모

- 이번 라운드에는 `src/**`, `index.html`, 설정 파일을 수정하지 않았다.
- 데모 모드 인증 우회 정책은 참고 사이트 데모 계정과 동일하다고 단정하지 않는다.
- 브라우저 캡처가 없으므로 시각적 개선을 보고하지 않는다. 구현 시 desktop/mobile에서 단계 라벨·CTA·대기 문구의 줄바꿈과 대비를 별도 검증한다.
